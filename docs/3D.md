# Airport illustration

The browser loads three original, unbranded, procedurally authored GLBs and one manifest from `web/public/models/airport/`. They contain no textures, external images or airline/airport logos. Duplicate exports, rendered movies and reference media are excluded.

Distances are deliberately compressed. Selected-hour `od` controls all parallel-runway directions; `p_18_usable >= 0.5` controls the illustrated runway-18 state. Routes and timing are fixed examples, not inferred traffic assignments. Play/pause, reduced-motion support and a 2D map fallback keep the forecast usable without 3D.

Blender uses +Z up and +Y north; glTF uses +Y up and -Z north. Convert positions `[x,y,z]` to `[x,z,-y]`. Runtime traffic and its geometric checks live in `web/src/lib/airport-traffic.ts` and its tests.

## Optional rebuilding

Source lives in `tools/blender/`. Install Blender separately. Its background build creates ignored `assets/airport/` output:

```sh
python -m venv tools/blender/.venv
# Activate this environment, then:
python -m pip install -r tools/blender/requirements.txt
blender --background --threads 2 --python tools/blender/build_airport.py -- --no-render
blender --background --threads 2 --python-exit-code 1 --python tools/blender/verify_assets.py
python tools/blender/publish_web_assets.py --check
```

To replace runtime assets after verification, run the publisher without `--check`, then check again. Blender is optional. Rebuilding and GPU rendering were not part of the public-package verification.
